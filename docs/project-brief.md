# 项目启动卡

这张卡用于选型前记录需求；未确定的字段标记“待确认”，不要让 AI 默默猜成无限流量或零预算。

| 输入 | 填写内容 |
|---|---|
| 业务与用户 | 展示什么、用户能修改什么、是否个性化 |
| 托管约束 | 已选平台、域名、地区要求；哪些可以调整 |
| 新鲜度 | 可接受票数延迟；是否必须推送；失败时可否展示旧值 |
| 流量模型 | 页面访问数、平均停留时长、同时在线数；来源和置信度 |
| 更新模型 | 公共 GET、个人 GET、POST、预检和发布任务的频率 |
| 预算 | 日/月可接受金额、币种、账号其他项目共享用量 |
| 数据正确性 | 幂等方式、持久化位置、是否容许丢票/重复票 |
| 费用响应 | 告警联系人、降级策略、执行权限、可容许检测延迟 |
| 验证边界 | 可以做哪些本地/线上操作；不能改变的生产资源 |

参考提问：

> 请先给出请求路径和成本模型，再实施这个项目。区别缓存命中降低了 SQL、CPU 还是动态入口调用。给出正常/增长/异常流量估算，说明共享月额度、计费窗口与排除项。优先评估共享读绕过动态收费入口的方案，但保留我的实时性和平台约束。写入先持久化并幂等，公共读失败不要静默回退到收费接口。交付时分别写明本地、提交、部署、线上缓存/WAF和计费验证状态。
